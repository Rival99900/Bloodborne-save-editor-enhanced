# v0.5.0 equipment insertion

Based on [valentinoamato’s f562c289 correction](https://github.com/Noxde/Bloodborne-save-editor/commit/f562c2893a4efdf3b281dc21dc89845c080d8d34) to the original [84adcfab insertion method](https://github.com/Noxde/Bloodborne-save-editor/commit/84adcfaba099d4d54ba98ae9c069fe77228706e9).

The upstream fix traverses 4096 variable-size GA records: equipment uses 60 bytes, upgrades 40, and empty slots 8. Inserting equipment replaces one 8-byte vacancy with a 60-byte block and shifts subsequent data by 52 bytes. Simply overwriting a 60-byte region of empty records does not preserve the slot count.

Enhanced applies this algorithm to both Inventory and Storage through one transactional method. It validates record types and vacancy markers, verifies the section boundary, rejects exhausted 16-bit handles and reference collisions, and checks destination capacity. The file length remains unchanged. The last 52 bytes must be zero padding; nonzero tail data is never silently discarded. This means some saves will be refused even where the upstream WIP would truncate them.

After insertion, all offsets and parsed character, inventory, storage, boss and position views are rebuilt. The candidate must pass the existing pre-save safety validation before replacing the active in-memory save. A failed operation leaves it unchanged. Existing replacement and item/upgrade paths remain available.

The upstream debug prints, absolute developer export path and intentional test panic are not included. Automated tests cover repeated weapon and armor insertion in both destinations, record headers, constant file size, shifted offsets, unchanged character values, reparsing and rejection without mutation. The operation remains explicitly experimental: parser tests do not establish PS4 game compatibility.

Validation on 2026-09-20: the data-handling Rust suite ran in a standalone harness using the unchanged production modules (71 initial passes; the sole fixture-path failure passed after restoring its test fixture link). All three final equipment integration tests and the GA parser rejection test passed. Full Tauri packaging and platform tests run in GitHub Actions.
