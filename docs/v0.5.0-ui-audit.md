# Local v0.5.0 UI audit

Based on local v0.4.1 (`2e3cff7`). No release, tag, push, or updater publication.

## Corrections

- Small Add/Replace canvas cards are 526 pixels wide, but text fitting previously allowed 680 pixels. Fit text to the actual canvas width and set the font before measuring, for small and full cards.
- The Chalice catalog shared the unfiltered Items branch. It now filters `Chalice` records.
- Catalog canvas options expose their complete names as accessible labels and tooltips.
- Remove the obsolete Add instruction recommending replacement instead of the now-enabled experimental insertion.
- Confirmation/status panels are bounded and scrollable in short windows, with wrapping for long titles and action labels.
- Add dialog content can scroll when its experimental notice consumes the available height. Remove a redundant legacy grid definition already overridden later in the stylesheet.
- Confirmation/status keyboard focus stays within the modal; Escape closes it and closing restores the previous focus where possible.
- Version metadata and navigation label updated to 0.5.0. Experimental insertion and existing save protections retained.

## Verification performed

- Production frontend build: passed (existing large-bundle advisory remains).
- 258 directly referenced UI translation keys across English plus 13 locales: no unresolved keys or tested encoding-corruption patterns. This checks resolved text; it does not prove every translation is idiomatic or detect all English fallbacks.
- Existing catalog audit: passed, including known residual English patterns and boss mappings.
- Existing localization checks: passed for catalog/effect searches, 43 teleport destinations, six groups, statistics, comparison messages and updater summaries.
- Server-rendered navigation check: passed for seven links, twelve NPC rows, and matching Inventory/Storage search headers.
- Whitespace/diff check: passed.

The browser reported `ERR_BLOCKED_BY_CLIENT` for the local server. No visual screenshot verification was completed. Rust/Cargo is unavailable here; native desktop compilation, equipment regression tests, and PS4 testing remain pending. These checks do not establish that the whole app is bug-free.

## Suggested next features (not implemented)

1. Save presets: a test character, chosen stat values, consumable quantities, and validated Gem/Rune presets, with a preview and one-step Undo. Do not present numeric stat edits as permanent invincibility.
2. Change comparison: show named fields/items before and after rather than only raw bytes; mark unknown fields clearly.
3. Build library: export/import character equipment plans and indicate which items are missing. Reuse the experimental confirmation for equipment creation.
4. Compatibility assistant: record the user-confirmed CUSA and game revision, backup status, and in-game test results without guessing a title ID from unverified bytes.
5. A separate optional cheat-file companion: read and validate supported GoldHEN JSON metadata, show title/version/process and export a reviewed file. Do not inject executable cheat patches into save bytes or auto-apply arbitrary offsets.

GoldHEN's documented cheat files target a game process (commonly `eboot.bin`) and are selected for a title ID and version. This is distinct from editing serialized save values. See the [official repository](https://github.com/GoldHEN/GoldHEN_Cheat_Repository). Persistent health/stamina freezing, game speed, or similar runtime effects would require separately researched, version-specific runtime support; no such functionality has been implemented here.
